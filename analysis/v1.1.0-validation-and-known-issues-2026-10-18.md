# v1.1.0 validation and known issues

Date: 2026-10-18

## Scope

This report records the failures found while repairing the original v1.0.0
installer, the changes included in v1.1.0, the real acceptance evidence, and the
remaining minimap rendering defect. It supersedes older experimental installer
designs. The release uses one linear Wine 10/Wineskin installation path.

## Installer problems found and fixed

### Steam bootstrap completion was detected incorrectly

The old installer waited for `Steam/package` after running `SteamSetup.exe`.
That directory belongs to the later Steam client update, so a successful
bootstrap could appear to hang indefinitely.

The installer now considers SteamSetup complete only after the setup process has
exited and both of these files exist:

```text
Steam/steam.exe
Steam/uninstall.exe
```

### Progress counters used Bash's special `_` variable

Using `_` as an arithmetic counter allowed Bash to replace its value with the
last command argument. This produced errors such as:

```text
((: SteamSetup\.exe: syntax error: invalid arithmetic operator
```

The counters now use ordinary named variables. Long waits report progress every
30 seconds and archive verification reports progress every 25 seconds.

### Steam did not reliably receive the game-install request

After successful authentication, the old flow could leave the user in Steam
without opening Pagonia's installation dialog. The repaired flow sends one
`steam://install/2155180` request after a successful login is detected and no
game manifest exists. Steam still requires the user to confirm the dialog.

### External prefix import complicated ownership and safety

The removed `--source-prefix` path allowed state from an unrelated Wine prefix
to enter the deployment. v1.1.0 creates its own controlled prefix or resumes one
staging directory marked by this installer. External prefix import remains an
unsupported option and is covered by a rejection test.

### Interrupted downloads had no narrow recovery path

v1.1.0 writes a versioned marker into its Steam/download staging directory.
Startup behavior is deliberately limited:

- no marked candidate: start Fresh;
- exactly one marked candidate: ask whether to continue;
- multiple marked candidates: stop instead of guessing;
- `--fresh`: ignore retained staging and create a separate deployment.

Publication and later graphics configuration are not treated as resumable.

### Overlapping Wineskin shutdown likely corrupted Wine server state

An intermittent Steam CEF exception initially looked like an out-of-memory
failure:

```text
Unhandled exception: 0xe0000008
```

The underlying Steam dump showed failed shared-memory creation:

```text
CreateFileMapping returned NULL (errno=2)
Failed creating file mapping SteamController_Master_mem
```

Wine's server still held files in an unlinked `/tmp/.wine-*` directory. The
likely trigger was an overlapping launcher shutdown/restart while Wineskin's own
cleanup removed its server directory.

The installer now serializes managed shutdown. It requests shutdown through the
prefix's `wineserver`, waits for Wine, Steam, Wineskin launcher, and debugger
processes, and requires two quiet polls before restart or move. Recursive
deletion performs a separate immediate process guard. The installer never
deletes Wine's `/tmp/.wine-*` directory itself. Failed or interrupted
Steam/download staging is preserved.

### Application deletion needed ownership checks

`--delete` now removes only the configured destination after checking the
installer marker and pinned Wine identity. It refuses deletion while related
processes remain and does not discover or remove staging directories, other
prefixes, or other installations.

### The generated application icon used promotional artwork

The old icon used Steam's portrait library capsule with padding. v1.1.0 instead
verifies and converts Steam's actual transparent Pagonia game icon:

```text
Steam/steam/games/341e435746d0f9bf5ef074ec0aa6e5e58e65226d.ico
SHA-256 809136e6b354ad4b335edc34fb2f6f547443fc0433c7c66068589b7dd20dbced
```

The published app receives the icon through the native AppKit workspace API.
The installer then unregisters and force-registers only the Pagonia app because
force-registration alone retained stale promotional artwork in the Apps view
opened from Dock. It does not reset the global Launchpad database.

## Real acceptance evidence

A real Fresh run completed this sequence under the pinned Wine 10 runtime:

1. SteamSetup bootstrap;
2. Steam update and authentication;
3. Pagonia download;
4. application configuration and publication;
5. game launch.

A separate real Resume run continued retained marked staging through publication
and game launch. Both the D3D12 device and swapchain were created:

```text
Created D3D12Device
Created D3D12 Swapchain
```

The user visually confirmed that the main world, terrain, water, buildings,
units, and interface render. The installer does not depend on Porting Kit,
Whisky, another game, Wine 11, or a transferred external prefix.

## Known graphics issue: blank minimap background

The game is playable, but the minimap background remains uniformly dark. Its
symbols and position marker render correctly. The same game content renders on
Windows and through the Linux vkd3d-proton path. Separate manual checks confirmed
that the game executable, material library, and core package match the verified
build. Current evidence therefore strongly implicates the macOS
D3D12-to-D3DMetal/Metal compatibility path rather than missing or corrupt game
assets.

The game contains distinct minimap pipeline factories for camera, exploration,
glyphs, terrain, and territory. Earlier logs contained:

```text
Unsupported: culldistance
```

The direct relationship of that message to the minimap terrain pipeline has not
been proven.

### Safe D3DMetal diagnostic run

The wrapper was restarted cleanly with:

```text
D3DM_LOGLEVEL_INFO=1
D3DM_DXIL_PROCESS_DEBUG_INFORMATION=1
OS_ACTIVITY_DT_MODE=YES
```

Metal API Validation and GPU Shader Validation were not enabled. The broken
minimap was reproduced, but the log contained no corresponding shader or
pipeline failure. Relevant output was limited to:

```text
Enabled MTL4 backend - options=RTV
Created D3D12Device
Created D3D12 Swapchain
Unsupported: Evict
Unsupported: MakeResident
```

There was no `Failed to materializeAll`, `Failed to compile a pipeline`, or
minimap-specific error.

### One-frame Metal capture

Apple's supported `/usr/bin/gpucapture` tool was used. Pagonia was launched with
`MTL_CAPTURE_ENABLED=1`, and the tool identified the game's Metal device,
command queues, and `CAMetalLayer: WineMetalView`. Exactly one layer frame was
captured:

```text
gpucapture start --pid <PID> --boundary <WineMetalView layer> --count 1
```

The resulting private diagnostic trace was approximately 4.1 GB. Xcode replayed
it and reproduced the blank minimap. The frame contained:

- 8 command buffers;
- 39 render encoders;
- 5 compute encoders;
- 39,231 draw calls;
- 3 dispatch calls.

Raw captured shader resources contain both:

```text
sv_culldistance0
sv_clipdistance0
```

This proves that Cull/Clip Distance semantics occur in the affected frame. It
does not yet prove that the relevant shader belongs to the minimap terrain pass.

Xcode remained in `GPUToolsPlatformSupport` resource-map construction at roughly
three CPU cores for an extended period and did not expose a completed mapping
from the blank minimap pixels to the responsible encoder, pipeline, and source
texture. The replay was stopped without modifying the app. The capture hook was
removed and all Wine processes were shut down through the prefix's wineserver.

### Current diagnostic conclusion

The exact compatibility-layer defect remains unknown. The remaining candidates are:

1. incorrect translation or handling of `SV_CullDistance` in the minimap camera
   or terrain shader;
2. an empty or incorrectly written minimap offscreen render target;
3. an incorrect resource barrier, copy, or final sampling/composite operation.

No shader patch is included in v1.1.0 because the failing draw has not been
identified. Guessing would risk the otherwise working world renderer.

The next focused diagnostic should capture one command buffer from each active
Metal command queue while the minimap is visible, rather than another complete
layer frame. Small queue captures can determine whether the minimap offscreen
texture is already blank, whether terrain draw calls produce fragments, and
whether the failure occurs only during final composition.

## Automated verification

The release is checked with Bash syntax validation, ShellCheck warning-level
analysis, focused Python regression tests for SteamSetup, Delete, Resume,
shutdown, and icon handling, plus `git diff --check`. The packaging/control-flow
simulation remains useful but cannot replace Steam authentication or a real
network depot download.

## Remaining release limitations

- The automatic post-login install request has not been independently accepted
  on a second genuinely fresh account/login state.
- A complete Fresh installation has not been repeated after every later
  lifecycle and icon-only commit; focused regression tests cover those changes.
- The minimap background defect remains unresolved.
- Steam, game, macOS, GPTK, or Wine updates may invalidate pinned behavior.
